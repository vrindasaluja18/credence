## 2024-10-14 - PyTorch einsum vs bmm overhead in sequential loops
**Learning:** `torch.einsum` introduces non-negligible setup/parsing overhead when invoked repeatedly inside time-step sequential loops (e.g., Bayes filter rollout over time horizon $L$). Replacing `torch.einsum("bc,brc->br", prior, Lk)` or `torch.einsum("bn,bnm->bm", prior, O)` with explicit batched matrix multiplication (`torch.bmm(Lk, prior.unsqueeze(-1)).squeeze(-1)` or `torch.bmm(prior.unsqueeze(1), O).squeeze(1)`) speeds up the Bayes filter step by ~20% with exact floating-point equivalence.
**Action:** Prefer `torch.bmm` or explicit tensor contraction operations over `torch.einsum` inside hot python loop iterations over sequence time steps.

## 2025-05-18 - Replacing nested loop bmm with single pre-contracted GEMM
**Learning:** Calling `torch.bmm` inside nested loops over actions $A$ and horizons $K$ for indexed positions incurs repeated tensor allocation and call overhead. ## 2025-05-25 - Caching data-independent Riccati sequences in linear-Gaussian Kalman filters

**Action:** In time-invariant Kalman filtering, cache data-independent Riccati gains $K_{g, t}$ and innovation variances $S_t$ across filter calls instead of re-evaluating covariance matrix recursions per sequence rollout.

## 2025-05-29 - Adaptive dispatch for action-conditioned belief propagation in POMDPs
**Learning:** Unconditionally using `self.T[a]` with `torch.bmm` in `_propagate` creates a critical memory bandwidth bottleneck when batch size $B$ or state dimension $N$ is large (such as in `window_filter`, where flattened batch $B = B_{\text{orig}} \cdot (L - W)$ easily reaches 5,000+). For `delayed_readout` ($N=128$), gathering `self.T[a]` allocates a $5120 \times 128 \times 128$ float64 tensor (~67 MB) on every time step. Selectively switching to per-action slicing (`out[m] = b[m] @ self.T[ai]`) when $B \cdot N \ge 4096$ avoids this memory allocation entirely while preserving `torch.bmm` for small tensors where kernel launch overhead dominates. This speeds up `window_filter` on `delayed_readout` by ~35x and overall window sweeps by ~28x with exact floating-point equivalence.
**Action:** In batched matrix indexing operations, dynamically switch from full batch gather to group-sliced matrix multiplication when the expanded tensor footprint exceeds cache thresholds.
